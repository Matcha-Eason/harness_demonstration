Harness Engineering

Harness 工程
给 LLM 套上夹具

一场围绕「输入 → LLM → 输出」这张图展开的概念阐释

Agent = Model + Harness

模型负责生成，harness 负责让生成的结果落在能用的范围里。harness 原义是马具，也是机床上固定工件的夹具。放到 agent 语境里，它指模型之外的所有代码，包括驱动循环、工具调用、上下文管理、输出校验、权限护栏。

后面每张图都遵守同一个坐标约定。横轴是交互时间，纵轴是信息空间。输出的线条散得越开，回答离可用越远。

本页动画，模型先空转。往下滚动，问题一个一个出现。

场景一 · 裸调用

需求明确、模型够强时，直接调就够了

一次输入，一次输出，线条笔直。这种情况下套 harness 是浪费，prompt 写清楚就能拿到好结果。

聊天问答、单轮翻译、格式转换都属于这一类。任务在一来一回之内结束，信息空间不需要扩张。

场景二 · 三种情况下输出会散

裸调用的输出是一个分布，常见三种发散

①问题本身难。一次输出装不下完整的解法，模型只能给出一部分，剩下的靠猜。
②模型偏弱。输出里混进过多的分支和槽位，有用的句子被噪音淹没。
③缺工具、缺信息。模型拿不到事实，靠参数里的印象硬编，幻觉和噪音一起放大。

右侧动画里，输出从一个点散成一个扇面。扇面越宽，落到可用区间的概率越低。

场景三 · Harness 登场

蓝线出现，输出被夹回通道之内

harness 在输出端加约束。它砍掉多余分支、滤掉噪音，把发散的回答收进一条窄通道。蓝线就是夹具，回答必须落在它之内。

这条蓝线落到工程里，是输出格式校验、工具白名单、上下文裁剪、权限边界、失败重试与回退。每一件都是普通代码，不依赖模型变聪明。

对比动画，同一批输出，加上蓝线前后的差别。

场景四 · 多轮放大

output 变成 new input，噪音逐轮滚雪球

agent 的工作方式是把上一轮的输出当作下一轮的输入。输入越复杂，输出的噪音越多，噪音又喂回模型，发散逐轮放大。

所以 harness 不能只在最後收一次尾，它要在每一轮都夹一次。每一轮的蓝线把误差按住，雪球才滚不起来。

动画里第二跳比第一跳更散，那是被放大的部分。

场景五 · 强化学习视角

夹具本身就是奖励的边界

good落在夹具内的回答，记为 good answer，给正奖励。
bad落在夹具外的回答，记为 bad answer，给负奖励。

训练的时候，harness 就是环境。它提供状态、执行动作、算出 reward，决定一个回合什么时候停。学习在多轮里发生，夹具的形状直接写进了梯度。

这也是为什么同一套 harness 最好同时服务训练与推理，两边不一致，模型学到的边界到了线上就对不上。

场景六 · 生产化

夹具力度拉到最强，换来生产确定性

生产环境把夹具拉到最紧。固定流程、决策模块、强校验一起上，输出被夹成几条平行的直线，每一次调用都可预期。

代价是灵活性。模型偶尔能给出的惊喜也被夹掉了。生产系统做这个交换是划算的，因为稳定可审计比偶尔出彩值钱。

落地 · 收个尾

框架与产品，以及一句话

框架层面，LangGraph 和 AgentScope 提供图结构与状态机，用来搭自己的 harness。产品层面，Claude Code、Codex 这类编码 agent 本身就是完整的 harness，模型只是其中可替换的零件。

经验上，模型变强会吸收掉一部分夹具，几年前的很多脚手架今天已经不需要了。但权限边界、运行环境、业务规则、记忆归属这些确定性要求，会一直留在 harness 里。

一句话说完，模型决定 agent 能做什么，harness 决定它每次做成什么样。

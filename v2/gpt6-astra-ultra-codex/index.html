概念核对与参考资料

保留原图中“发散 → 加入边界 → 多轮纠偏 → 稳定交付”的视觉隐喻，并依据一手资料补充上下文、工具与状态管理。下列链接是概念依据；动画中的形状、轮次与任务结果均为教学设计。

01 / HARNESS
Anthropic · Demystifying evals for AI agents ↗

Agent harness 负责处理输入、编排工具调用并返回结果。评估对象是模型与 Harness 的组合；评价应检查真实任务结果，而不只看最终回答。

02 / LONG-RUNNING AGENTS
Anthropic · Effective harnesses for long-running agents ↗

长任务需要跨会话保留工作状态、增量推进并验证完成情况。上下文压缩本身不能替代任务规划、进度记录和端到端测试。

03 / ENGINEERING PRACTICE
OpenAI · Harness engineering ↗

工程工作包含设计环境、表达意图和建立反馈循环。将必要的边界转为可执行检查，同时为边界内的实现保留自由。

04 / TRAINING VS. INFERENCE
Ouyang et al. · Training language models to follow instructions with human feedback ↗

人类偏好可用于训练奖励模型，再通过强化学习优化语言模型。演示将“运行时把反馈加入下一轮输入”与“训练时更新模型参数”明确分开。

如何理解这张图：Harness 是围绕模型工作的运行系统，也包含支持它的工程环境。两条“夹具”线是视觉隐喻：它能组织输入、执行动作、限制边界、检查结果和恢复失败。更窄的扇面不等于更高的事实正确率；更强的限制也不天然更好，应通过任务评估来选择。

从原始手绘，到六幕动画

  1. 输入 → LLM → 输出保留模型作为中心，并把“用户价值 / 交互时间”转为可验收结果与交互成本。
  2. 难问题、能力不足、信息缺失三种发散诱因可切换。扇面只是风险与偏离的视觉比喻。
  3. 两条蓝色的 Harness 夹具用紫色轨道逐渐收束；补上输入侧上下文和执行边界。
  4. 多轮中的再输入结果经工具、验证和状态更新回到模型。检查让下一轮获得纠偏证据。
  5. Good / Bad Answer区分运行时筛选、重试与训练时强化学习；两者都能用反馈，但更新对象不同。
  6. 生产化 Agent用一个“修复登录问题”的模拟流程，展示验收、停止与交付。AgentScope、LangGraph 等框架可承载部分编排，但框架本身不保证可靠性。

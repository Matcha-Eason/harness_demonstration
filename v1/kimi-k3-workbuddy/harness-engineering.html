概念阐释

Harness Engineering

驾 驭 工 程

给大模型套上挽具，让输出空间可控

harness 的本义是马具、挽具。人给马套上它，马的力气才能按人的方向使出来。 这个概念 2026 年初由 Mitchell Hashimoto 提出，OpenAI、LangChain 跟进阐述， 核心公式是 Agent = Model + Harness。
Mitchell Hashimoto · 2026.02 OpenAI · 人类掌舵，智能体执行 LangChain · Agent = Model + Harness
起点

裸模型直连，一切顺利的前提

用户给一句话，模型直接给答案。这条路能走通，要同时满足两个条件， 问题本身不难，模型本身够强。两个条件缺一个，输出就开始漂。

问题

输出空间为什么会炸开

① 问题难推导链条长，每一步都在概率上采样，误差一路累积，输出空间被摊大。
② 模型弱能力兜不住任务，回答里掺进多余的槽位和废话，噪音变多。
③ 缺工具、缺信息模型拿不到事实，只能用想象补位，幻觉和噪音一起放大。
背景规律

交互越久，需要约束的信息空间越大

单轮问答的问题不大。任务一旦拉长成几十轮的工具调用和对话， 上下文越积越多，模型的可选输出随之膨胀。harness 要解决的就是这条往上翘的曲线。

核心动作

给 LLM 套上挽具

夹具可以由很多东西做成。系统提示、结构化输出格式、权限边界、工具白名单、 校验器、测试、回退逻辑。它们共同的特征是写在模型外面， 用代码强制执行，模型自己绕不过去。

多轮场景

噪音会随轮次滚大，夹具负责截断

上一轮的输出会变成下一轮的输入。输入越复杂，输出越嘈杂，一轮一轮滚下去就失控。 夹具架在轮次之间，只有落在允许范围内的输出才能进入下一轮。

更进一步

用强化学习让模型自己学会待在夹具里

夹具同时划出了奖励的边界。落在夹具内的回答给正奖励，跑出夹具的回答给负奖励， 多轮训练之后，模型自己就往夹具里收敛。外部约束慢慢变成模型的内部习惯。

落地形态

生产级 Agent，用极强的夹具换确定性

  • Demo 可以容忍偶尔答非所问，生产线不能。支付、运维、医疗场景里，一次跑飞就是事故。
  • 所以生产级 Agent 把夹具收到最紧，固定流程、固定 schema、固定工具集，用灵活性换确定性。
  • AgentScope、LangGraph 这类框架干的也是这件事，用图结构和状态机把模型的行动路径钉死。
调研核对

这套思路在公开资料里对得上

  • 2026 年 2 月，Mitchell Hashimoto 提出 Engineer the Harness。智能体每犯一次错，就造一个机制让它永远不再犯。
  • OpenAI 跟进发文，围绕 Codex 阐述同一理念，口号「人类掌舵，智能体执行」。
  • LangChain 给出公式 Agent = Model + Harness，模型负责推理，harness 负责执行环境、工具、状态、约束和验证。
  • 业界分层，前馈的叫 Guides（提示、schema、规则），反馈的叫 Sensors（测试、校验、评估），手稿里的「夹具」同时包含这两类。

要点回顾

把图画成一句话

Agent = Model + Harness
  • 模型的输出空间天然会发散，难题、弱模型、缺工具缺信息都会把它摊得更大。
  • 多轮交互让噪音滚动放大，夹具架在轮次之间负责截断。
  • 夹具写在模型外面，用代码强制执行，提示词说服不了的事，结构能强制。
  • 强化学习把夹具变成奖励边界，让模型自己学会待在里面。
  • 生产环境的答案是极强的夹具力度，换来输出的确定性。
